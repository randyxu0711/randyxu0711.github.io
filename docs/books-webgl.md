# 書架 WebGL 版規格

狀態:2026-10-12 取代 CSS 3D 版成為 `/books/`(先在 `/books-3d/` 做原型)。下面的「技術」一節寫的是原型的路徑,現在版面是 `_layouts/books.html`。

## 為什麼要改

錄了一次換排法的效能紀錄(桌面 Brave,165Hz 螢幕):

- 換排法時實際約 95–110 fps,大約每 3 格掉 1 格;平常捲動不掉格。
- 封面點陣化共 16ms、圖片解碼 4ms:**抓圖與解碼不是瓶頸**。
- 掉的格幾乎都標記「沒有主執行緒動畫」:滑動與轉身確實在合成層跑,**卡在合成器與 GPU 程序**。
  每一個書面都是一個圖層,畫面裡 100–150 本書 × 4 面,每一格都要整理幾百個圖層。
- 按下按鈕時主執行緒卡 40–65ms + 20–30ms(搬 DOM、建立幾百個動畫)。

畫面外的排已經不繪製,所以「少載幾排」沒有幫助;CSS 3D 能做的優化(少圖層、縮短波浪)都只是緩解。
WebGL 把整個書架交給 GPU 一次畫完,物件數量幾乎不影響成本,而且有真的鏡頭與打光。
目的:**更好的效能,以及 CSS 做不到、讓人驚豔的動畫**。

## 參考

- Google WebGL Bookcase(2011):鏡頭飛到選的主題,用移動告訴你在哪;點書抽到中央。
- Bookish(Framer):沿著書架拖曳、方向鍵一本本移動。
- 3D Bookshop(three.js 論壇):被抱怨 17.8MB 太重、載入 5–9 秒、書穿過層板。
- 3D 鏡頭的實務共識:限制鏡頭(不翻轉、不自由旋轉)避免迷失;捲動控制要加阻尼。
- Bohemian Bookshelf(CHI 2012):偶然的發現來自同一批書的多種排列與相鄰關係 → 多種排序。

## 動線

只有兩層:**逛**與**拿起一本**。從遠處看整面牆只出現在過場裡,不是一個要退回的狀態。

1. **頁面照常往下捲**(原生捲軸與慣性),鏡頭沿著書櫃往下移,固定在書脊字清楚可讀的距離
   (桌面約 15–20 本書脊一個畫面寬,手機約 8–10 本)。鏡頭不轉、不翻,只上下移動。
2. **分組排序(星等、年份)**:每組是一條長層板,比畫面寬時**層板自己左右滑**(鏡頭不動):
   拖曳、觸控板橫滑、`←` `→`、層板兩側的箭頭鍵。一般滑鼠滾輪只捲頁面,不被攔截。每層記住自己滑到哪。
   比畫面寬的層,層標題的本數改成「34–52 / 133 本」(畫面裡是第幾本到第幾本),下面一條細線標出這段在整層的位置;
   跟著滑動更新(只在滑動的那幾格算,`layout.js` 的 `inView`),放得下一個畫面的層不顯示。
3. **連續排序(顏色、作者)**:不分組,書依序排滿,每一層剛好一個畫面寬(像文字換行),只上下捲。
   手機陳列一層放 3 本封面(以前 2 本,269 本要捲 42 個畫面;封面約 100–110px 寬)。
4. **浮動工具列**(固定在畫面下方,任何位置都能按):
   - 排法:直立 / 陳列
   - 排序:星等 / 年份 / 顏色 / 作者(之後可能加「地區」、有標籤再加「題材」)
   - 寬螢幕一行放全部的鍵,排法與排序中間一條分隔線。
   - 窄螢幕(≤ 640px,同分享頁)收成一行兩個鍵,約一個按鍵高(390px 寬時 50px):
     左邊是排法的圖示鍵(直立 / 陳列切換,圖示是目前的排法,`aria-label`「陳列」+ `aria-pressed`);
     右邊是「星等 ▾」,按下在工具列上方展開排序選單(同一組排序鍵改成直排,目前的按下)。
     選了就收起、照常洗牌;Esc、點外面、焦點離開都會收起,Esc 與選完焦點回到「星等 ▾」。
     點外面只收選單,不會同時拿起書。
5. **錨點**:換排法或排序時,以換之前畫面中央的那本書為錨點,換完捲動與層板位置調整到它仍在畫面中央。
6. **層標題**:HTML 浮在畫面左上,跟著捲動換成目前那一層(星等與本數 / 年份 / 作者首字母 / 顏色不顯示)。
7. **索引軌**(畫面右緣,桌面與手機都有):目前排序的段落,星等 / 年份分組、作者首字母(非拉丁字母併成一段)、
   顏色(色相分段,用那段中間那本的顏色,黑白灰最後)。**每段長度跟本數成比例**,
   軌道本身就是分布圖。目前位置是一條橫線、目前那段變粗,前面的段變深(同 About 的段落捲軸)。
   點、拖曳直接捲到那裡(原生捲動,鏡頭照常跟著);分組排序只上下跳到那一組,不動層板的左右。
   標籤只在游標停留、拖曳、鍵盤聚焦時浮出(手機不常駐,不擋書)。每段是按鈕(`aria-label` = 名稱與本數),`<nav>` 有標籤。
   段落與比例是 `layout.js` 的純函式(`sections`),從排序算,跟層怎麼排無關。
8. **拿起**:點一本書 → 飛到鏡頭前、封面朝前 → 再點翻到封底 → Esc、點空白處或焦點離開就放回。
9. 選擇的排法與排序存在 localStorage(`books3d-view`、`books3d-sort`),網址不帶參數。

## 排序與分組

| 排序 | 分組 | 組內順序 |
|---|---|---|
| 星等(預設) | 5、4、3、2、1、未評分 | `books.json` 的順序(與現在相同) |
| 年份 | 讀完年份,新到舊;不到 12 本的年份跟相鄰也不到 12 本的併成一組(2020–2022);沒有日期的放最後一組 | 讀完日期新到舊 |
| 顏色 | 不分組 | 依 `color` 的 OKLCH 色相;彩度很低的(白、灰、黑)放最後,依明度排 |
| 作者 | 不分組 | 作者原文名 `localeCompare`,同作者依讀完日期 |

## 動畫

只動 GPU 端的數值(每本書的位置、旋轉);JS 每格只更新一串數字。**沒有在動的時候不重畫**(省電)。

- **換排法(直立 ↔ 陳列)**:每本書原地轉 90 度,間距同時重新分配。由左到右一波,整段 ≤ 1 秒。
- **洗牌(換排序)**:鏡頭先拉遠到看得到整面牆,書沿著**弧線**飛到新位置(離得越遠,弧越高),
  依飛行距離錯開出發時間;落定後鏡頭推近到錨點那本書。整段約 1.6 秒。
- **隔壁的書倒向空位**:拿起一本,左右兩本以底邊為軸微微傾向空出來的縫(約 6–8 度,彈簧);放回時被推正。
- **撥書**:游標劃過書脊時,經過的書依游標速度往前傾一下再彈回,一波一波。手機上是手指橫向拖曳時。
- **游標停留 / 鍵盤聚焦**:書往外滑出一點,底緣亮琥珀(琥珀三個時刻的規則照舊)。
- **燈(2026-10-23 起,見 `docs/study-room.md`)**:白天是窗戶從身後來的柔光 + 天光;夜間是右前方的落地燈(位置跟著畫面,一直在右邊),不跟游標、也不跟拿起的書;拿起的書用固定柔光(`HELD_FINISH`)。三個場景都用 three.js 內建材質與陰影貼圖。
- `prefers-reduced-motion`:不飛、不轉、不撥,直接到位。

## 畫面

- **風格**:介於現在與寫實之間。一盞柔和主光 + 環境光,圓弧書背與書頂的明暗由光產生;霧面,沒有反光與木紋,
  不做景深、光暈。層板只有上面與前緣(跟現在一樣),書後面就是桌面。
- **顏色從 token 來**:桌面 `--desk`、層板 `--shelf`、書口與書頂 `--paper` / `--paper-deep`、琥珀 `--edge`。
  用 1px 的 2D canvas 填色再讀像素轉成 RGB(oklch 在 JS 端不好解析)。主題切換時(`data-theme` 變更或系統主題改變)重讀並重畫。
- **書**:InstancedMesh,一次繪製。尺寸跟現在一樣:厚度 = 頁數 ÷ 11(18–50),高度 = 封面寬 ÷ `ratio`(0.55–0.78)。
  顏色 `color`、書脊字色 `ink`。
- **封面**:跟現在一樣先載 `._SX150_`,畫進一張(或幾張)拼貼貼圖;拿起時那本換 `._SX400_`。
  Amazon CDN 回 `access-control-allow-origin: *`,圖片設 `crossOrigin = 'anonymous'`。
  載入前書是純色;載不到退回原圖,原圖也載不到就用書的顏色 + 書名(畫進貼圖)。
  先照這樣做,實測不卡的話再考慮直接載大圖。
- **書脊字**:用 2D canvas 畫成拼貼貼圖。中文逐字直排、英數轉 90 度(對應現在的 `text-orientation: mixed`),
  字級 = 書脊可用高度 ÷ 書名長度(規則同 `spine-length.rb`)。等 `document.fonts.load` 拿到宋體再畫。
  換語言(`langchange`)時重畫:中文顯示 `books_zh.yml` 的譯名,沒有就顯示原文。
- **封底**:拿起時才畫:書名(目前語言在上、另一種在下)、作者、讀完年份、次數、頁數。
  Goodreads 連結是疊在封底上的 HTML 按鈕(可 Tab、可點、螢幕閱讀器讀得到)。
- 像素比上限 2。

## 載入

- 有 JS 時書架區一開始蓋著暗幕,純 HTML 書單也不顯示(都由 CSS 決定,首次繪製就對)。
- 幕是場景的一部分,不是一塊布。只蓋暗幕、等封面時整片全黑,看起來像在 loading。
  - 夜間:場景第一格就以同樣的暗度畫出來,暗房裡只隱約看得到書架與書的形體(讀不到字)。
  - 白天:反過來,紙色上的墨線素描(每個面的邊框),像打稿。
  - 開燈前不給任何互動回饋(檯燈、停留、撥書、拿起、層板滑動),不然會被看穿只是空模型。
- 畫面裡的封面貼好(至少 300ms 讓開場被看見、最多 1.5 秒,不再看網路決定)就「開燈」:
  夜間像檯燈開關閃兩下再亮;白天顏色從畫面中央像水彩一樣暈開,線條退去。
  工具列、層標題、索引軌在燈亮時出現;之後才到的封面與書脊字一本本淡入。
- 每次載入都開場,長短看資料:封面在最短的 300ms 內就到齊(多半是快取)時播短版(夜間閃一下就亮、白天暈開 0.6 秒),
  有在等才播完整版。開場是用來掩護等待的,沒在等就快速帶過。
- three.js 與自己的程式用 `modulepreload` 一起抓,不等 main.js 下載完才發現 import(import map 要放在 preload 前面)。
- 試過「書一本本落到架上」的進場動畫,封面還沒到時看起來是一堆純色盒子,不用。

## 保底與無障礙

- 頁面輸出一份純 HTML 書單(`<ol>`,依星等分組:書名、作者、星等、Goodreads 連結)。
  沒有 JS、WebGL 開不起來、three.js 載入失敗時就顯示這份;搜尋引擎、Ctrl+F 也讀這份。
- WebGL 啟動成功後,書單改成視覺上隱藏(`visually-hidden`)但保留給螢幕閱讀器與鍵盤:
  每本書是一個按鈕,Tab 到它時場景裡那本書高亮並捲到畫面中,Enter / 空白鍵拿起。canvas 本身 `aria-hidden`。
- 書單的順序跟著目前的排序更新。

## 技術

- three.js 固定版本(r170),放 `assets/vendor/three/three.module.min.js`,不用 CDN。
  用 `<script type="module">` 只在這一頁載入。
- 程式放 `assets/books3d/`,**不放 `assets/modules/`**(那裡的檔案每頁都載入)。
- 版面 `_layouts/books-3d.html`,頁面 `books-3d.md`(`permalink: /books-3d/`、`sitemap: false`、`noindex: true`)。
  `head.html` 依 `page.noindex` 輸出 `<meta name="robots" content="noindex">`。不放進導覽列。
- 書的資料由 Jekyll 輸出成 `<script type="application/json">`:id、書名(原文 / 中文)、作者(原文 / 中文)、星等、
  頁數、讀完日期、次數、color、ink、ratio、cover、url、書脊長度(`spine_length`)。
- `_plugins/books-page.rb`:書單是空的或 books 模組關掉時,`/books-3d/` 也不產生。
- 介面文字照舊放 `_data/i18n.yml`。
- 點擊判定用 raycast 打到哪本書。

## 效能目標

- 桌面換排法與洗牌:跟得上螢幕更新率(165Hz 下掉格率明顯低於現在的 1/3)。
- 按下按鈕的那一格,主執行緒 < 16ms(只算新位置,不搬 DOM)。
- 首次載入:three.js(壓縮後約 170KB)+ 自己的程式 + 269 張 150px 封面(約 2–3MB,陸續載入)。
  書的形狀與顏色在 JS 載入後一格內出現。
- 靜止時不重畫。

## 分階段

每個階段結束都能建置、能在 `/books-3d/` 打開試。PR 1 給你實測手感與效能,再做 PR 2。

**PR 1**
1. 路由、資料、保底書單、three.js 載入;書是純色盒子站在層板上,捲動帶動鏡頭,顏色來自 token、晝夜切換。
2. 封面與書脊字貼圖、換語言。
3. 直立 / 陳列 + 換排法動畫 + 錨點 + 浮動工具列 + 層板左右滑 + 層標題。

**PR 2**
4. 五種排序 + 洗牌 + 鏡頭拉遠推近。
5. 拿起、翻封底、Goodreads 連結、隔壁倒向空位、撥書、停留 / 聚焦。
6. 無障礙書單與場景連動、reduced motion、靜止不重畫的檢查、檯燈實驗。

## 驗收

- Docker 建置通過、htmlproofer 通過;`/books/` 完全不受影響。
- 你在桌面(Brave)與 iPhone 上手動試;桌面再錄一次效能紀錄,跟這份開頭的數據比較。
- 關掉 JS(或停用 WebGL)時,`/books-3d/` 顯示完整的 HTML 書單。

## 決策紀錄

- 2026-10-19:269 本時有些排法太長(手機陳列連續排序 135 層、約 42 個畫面;3★ 那層約 44 個畫面寬)。
