膠框的構造

立體感是四層疊出來的,每一層都是一個 token,可以個別調整或關掉。下面從左到右,一次加一層。

1. 平面卡片

內容區加上投影。到這一步就是一般的卡片。

2. 加一圈樹脂框

內容區往內縮 --rim,露出的那一圈是半透明琥珀。

3. 邊緣與內凹

框的上緣亮、下緣暗,內容區有內陰影,看起來像嵌在框裡。

4. 透光

縮圖模糊後透進樹脂,卡片下方映出琥珀色的光影。沒有縮圖的卡片就只有琥珀色。

框的厚度表示重要程度:精選 12px、一般 9px、搜尋結果 5px。圓角也跟著角色走:外框 20px,內容區等於外框減掉框厚,標籤是膠囊形。

元件

用目前站上的四則 share 和兩個 project 示範。每個元件都只吃 front matter 裡已經有的欄位,沒有的欄位就收起來,不留空位。

篩選不換頁。tag 可以複選,篩選結果會記在網址上(例如 /#security),複製給別人看到的就是同一組。原本的 tag 頁面就不需要了。

可以只用鍵盤操作。你的訪客多半是工程師,這個會用得到。

之後可以加的功能

GitHub Pages 只能放靜態檔案,但搭配 Actions,功能可以在三個時機執行:發文時(issue 觸發 Action)、定期(Action 排程),或是在訪客的瀏覽器裡(讀建置時產生的 JSON)。下面的功能都在這三種範圍內,不需要伺服器。

每個功能都是獨立模組,可以單獨開或關。外框標起來的那個,是我最推薦先做的。

保存

跟琥珀的概念最貼近的一組。轉發的價值在於原文還連得到,但連結遲早會失效。

封存備份 發文時定期

發文時請 Wayback Machine 存一份,封存網址寫進 front matter。之後每週檢查原文還在不在,失效的卡片會改連封存版,並標示「原文已下架」。

縮圖備份 發文時

og 圖片現在是直接連到對方網站的,對方一換網址就破圖。可以選擇在發文時縮成小圖存進 repo。

模組要遵守的規則

規則為什麼
關掉 JavaScript,卡片和連結照樣能用模組只負責加功能。就算它壞掉,也不會讓整頁看不到
模組之間不互相呼叫,只共用建置時產生的 shares.json關掉任何一個,其他模組照常運作
樣式只引用語意 token換外觀時,模組不用跟著改
新增欄位一律選填,舊文章沒有這個欄位也要能顯示開一個新模組時,不用回頭補舊資料
有 action.py 就要有測試跟現在 tools/share 的規則一樣

不論框架最後選 Jekyll 還是 Hugo,這套結構都套得上:插槽對應到 include 或 partial,shares.json 兩邊都能在建置時產生。

Template 化

目標是別人 fork 之後,改 4 個設定就能變成自己的站,完全不用碰 CSS。做法是把樣式分成三層,上層只能引用下層。

原始值

色相、彩度、框厚、圓角、字型。template 使用者只改這層。

--h: 72; --c: 0.15; --rim-card: 9px;

語意 token

底色、文字、樹脂、光影。晝夜各一組,用 oklch 從色相算出來,換色相時兩套會一起變。

--resin: oklch(0.82 var(--c) var(--h) / 0.55);

元件

膠框材質 .gel 加上內容區。元件只引用語意 token,不寫任何色碼。

.gel { padding: var(--rim); }

使用者要改的設定

# _config.yml
theme:
  hue: 72          # 主色色相。琥珀 72,試試 200 是海玻璃、340 是玫瑰石英
  chroma: 0.15     # 彩度,0 就是無色透明壓克力
  mode: system     # system / light / dark
  rim: 9px         # 一般卡片的框厚,精選和搜尋結果會跟著等比例變

情況處理方式

需要你決定的事

  1. 首頁用 B(精選加格狀,上方可以篩選)嗎?

    或者你比較想保留現在的單欄。

  2. 縮圖透進框裡這個效果要留嗎?

    這是外觀上最有辨識度的地方,代價是每張卡的框色都不一樣。

  3. 第一批要做哪些模組?

    我的建議是書架篩選、已開過、封存備份。前兩個改變使用體驗,第三個最能代表這個站。

  4. Template 要開放到哪裡?

    外觀、內容類型、模組三類都開放,或是第一版只開放外觀和模組。
